### US-015: Harden the origin server and site response hygiene
**As a** visitor and site owner, **I want** the origin to send modern security headers, redirect www to apex, refuse dotfiles, and serve a branded 404 **so that** the site does not leak files or lack baseline browser protections.
**Points:** 5
**Status:** In progress
**Acceptance criteria:**
- [ ] Given any request served by `server/contact.py`, when the response arrives, then `Strict-Transport-Security`, `X-Content-Type-Options`, `Referrer-Policy`, `X-Frame-Options`, and `Permissions-Policy` headers are present, with a CSP shipped in `Content-Security-Policy-Report-Only` mode
- [ ] Given a request whose Host is `www.tetrazero.com`, when any path is requested, then the origin responds 301 to `https://tetrazero.com` + the original path and query
- [ ] Given a request for a dotfile such as `/.htaccess`, when the origin handles it, then it returns 404 instead of serving the file
- [ ] Given a request for a path not in `dist/`, when the origin responds, then it returns the built `404.html` page with status 404 instead of Python's default error page
- [ ] Given traffic arrives via Cloudflare → Caddy, when the contact rate limiter identifies a client, then it uses `CF-Connecting-IP` (falling back to the rightmost `X-Forwarded-For` hop, then the socket address) so the key cannot be spoofed by a client-supplied XFF
- [ ] Given `server/contact.py` is committed, when deploy runs `git pull` on the server, then no untracked-file conflict blocks the deploy
- [ ] Given the user systemd unit is installed by deploy, when the service starts, then it runs with `NoNewPrivileges=true`, `PrivateTmp=true`, and `ProtectSystem=strict`

Source: `docs/security-audit-2026-11-18.md` findings 2, 3, 5, 6, 7, 8, 9 (finding 1, the webhook, is explicitly out of scope per the owner).

**Evidence (local, pre-deploy, 2026-11-18):** with `npm run build` output in `dist/`,
`server/contact.py` was run on 127.0.0.1:3080 and curl-verified: all six security headers
present on every response; `Host: www.tetrazero.com` → 301 to
`https://tetrazero.com/some/page?q=1`; `/.htaccess` → 404; `/nonexistent-xyz` → 404 with
the built branded page; `GET /api/contact` → 405; 6 rapid POSTs → 429 on the 6th (limit 5);
`/../server/contact.py` → 404. Boxes stay unchecked until the same checks pass against
production after deploy (which also installs the sandboxed user unit and resolves the
untracked-file conflict).
