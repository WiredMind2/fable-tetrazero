### US-018: Contact form goes through the server relay, webhook hidden from clients
**As a** site owner, **I want** the contact form to POST to my own origin, which alone holds the Discord webhook **so that** visitors cannot extract the webhook from the page source.
**Points:** 3
**Status:** Done
**Acceptance criteria:**
- [x] Given the deployed homepage, when its HTML and JS are searched, then no Discord webhook URL (or base64 thereof) appears anywhere in the bundle
- [x] Given a filled contact form, when it is submitted, then the browser POSTs to same-origin `/api/contact` and the server forwards it to Discord via `contact.secret`
- [x] Given a bot that fills every field, when it submits including the hidden `website` honeypot, then the server responds `ok:true` without delivering anything to Discord
- [x] Given the server rejects a submission (validation, rate limit, or delivery failure), when the client receives it, then the form surfaces the server's error message
- [x] Given `src/config/settings.ts` only existed to carry the webhook, when the relay switch lands, then the file is deleted and nothing imports it

**Evidence (production, 2026-11-19):** `grep -c aHR0cHM6Ly9kaXNjb3Jk` on live homepage = **0**
(whole `dist/` clean); built page contains `api/contact` + `name="website"` honeypot;
honeypot POST → `{"ok": true}` 200 (nothing delivered); real labeled test POST →
`{"ok": true}` 200 (message delivered via `contact.secret` — confirmed in Discord);
`GET /api/contact` → 405; error paths verified locally (400 Invalid email / Message too
short / subject is required, all surfaced as JSON `error`). `settings.ts` deleted, zero
remaining importers (grep verified).

Note: the previously leaked webhook remains valid until rotated in Discord — hiding it stops new leaks but does not revoke old copies (owner accepted this risk for a low-value channel).
